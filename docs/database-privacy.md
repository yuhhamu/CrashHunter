# CrashHunter データの取り扱い

制定日: 2026年11月19日

CrashHunter(以下「本ソフト」)は、作者 yuhhamu が無料で配布する、Mod に対応したサードパーティ製の Minecraft ランチャー(以下「ランチャー」。対応しているランチャーは README に記載)のインスタンスが落ちる原因を調べて直すためのソフトです。このページでは、本ソフトがインターネットに送る情報と、その扱いを説明します。

## 1. 基本方針

- 本ソフトの診断・原因特定・構成調整・自動修正は、すべてお使いのPCの中で行います。
- インターネットに情報を送るのは、次の4つだけです。
  1. CrashHunter Database の利用(データベースを使う)
  2. CrashHunter Database への報告(結果を送る)
  3. 原因特定・構成調整の記録の送信
  4. 更新の確認
- 1〜3 は、初期値ではオフです。オンにしたものだけが動きます。
- 名前・メールアドレス・Minecraft のアカウントなど、あなたを直接特定できる情報は取得しません。

## 2. 設定と送る情報

| 設定 | 初期値 | 送るタイミング | 送る情報 | 保存 |
|---|---|---|---|---|
| データベースを使う | オフ | 診断画面を開いたとき、構成調整を始めたとき、配布データを取得するとき | 有効なModの一覧(下記「Modの情報」)、Minecraft とローダーのバージョン。配布データの取得では Minecraft とローダーのバージョンだけ | しない(照合にだけ使います) |
| 結果を送る | オフ | 原因が確定したとき、修正が効いたとき・効かなかったとき | 下記「報告の内容」 | する |
| 原因特定・構成調整の記録を送る | オフ | 原因特定・構成調整が終わったとき | 下記「記録の内容」 | する |
| 起動時に更新を確認する | オン | 起動時に1回 | なし(GitHub にリリース情報を問い合わせるだけ) | — |

「結果を送る」と「記録を送る」は、「送る前に中身を確認する」がオンのとき、送るたびに内容を表示します。確認画面で送らないこともできます。

### Modの情報
Modのjarのハッシュ(SHA-1 と CurseForge 照合用のハッシュ)、modId、バージョン。

### 報告の内容
- 落ちるModの組み合わせ、壊れたファイル、対処法と直らなかったバージョン、起動できた構成(有効なModの一覧)
- 原因のModと、それが動くのに必要だったMod(前提Modを宣言していたかどうか)
- クラッシュの内容: 例外の名前とメッセージ、原因の連鎖、スタックの上位(クラス・メソッド・行番号と、どのModのものか)、起きた段階、Mixin などの失敗の詳細、関わったMod、同じクラッシュが起きた回数
- 環境: Minecraft・ローダー・Java のバージョン、OS の種類と大まかなバージョン、クラッシュレポートのシステム情報の一部(メモリ、CPU、GPU とドライバのバージョンなど)
- 端末ID(下記)
- ゲーム中に起きたクラッシュは、「送る前に中身を確認する」がオフのときだけ送ります。同じクラッシュは1日1回までです。

### 記録の内容
Minecraft とローダーのバージョン、Modの情報、設定値(並列数・待ち時間など)、各試行の結果と所要時間、クラッシュの特徴(ハッシュと例外の種類)、見つかった原因、構成調整で行った変更、端末ID。

### 端末ID
本ソフトが作る、PCごとのランダムな値です。回数の制限、重複の判定、削除の依頼に使います。サーバーには、そのままではなく変換した値(ハッシュ)だけを保存します。

## 3. 送らない情報

- ユーザー名、Minecraft のアカウント
- フォルダのパス、インスタンス名、ワールド名、jarのファイル名
- ログやクラッシュレポートの全文
- CurseForge・Modrinth から取得した情報

メッセージやエラーの行に含まれるパスやユーザー名は、送る前に本ソフトが消します。サーバーでも同じ処理をします。

通信の仕組み上、サーバーにはIPアドレスが届きます。IPアドレスはそのままでは保存せず、回数の制限と不正な送信への対応のために、変換した値(ハッシュ)としてだけ保存します。

## 4. 利用目的

送られた情報は、次の目的にだけ使います。

- Minecraft のバージョンとローダーごとに集計し、配布データとしてほかの利用者の診断・原因特定・構成調整・自動修正に役立てること。配布データは予想として使い、本ソフトは必ず実際の起動で確かめます。
- Modの開発者が、自分のModの不具合や競合を知るための集計を作ること
- 本ソフトの探し方や待ち時間を改善すること
- 不正な送信を見つけて止めること

## 5. 第三者への提供と公開

- 集計データは一般には公開しません。本ソフトを通してだけ使われます。
- 請求があれば、集計データを提供することがあります。特定の個人やModへの攻撃が目的と明らかな請求には応じません。
- Modの開発者に、そのModに関する集計(クラッシュの内容、競合、対処法、前提Modの関係)を提供することがあります。複数の端末から報告されたものに限ります。
- どの場合も、送られた報告そのものと端末IDは提供しません。
- 情報を売ることはありません。
- サーバーは Cloudflare(Workers・D1・KV)を使って運用しています。

## 6. 保存期間

- 報告と記録には保存期限を設けていません。削除の依頼があれば削除します。
- 集計データは、端末と結び付かない形で保存し続けます。

## 7. 削除の依頼と送信の停止

- 設定の「送った報告の削除を依頼」で、その端末IDの報告と記録をすべて削除します。あわせて端末IDを新しくするので、以後の報告は削除した報告と結び付きません。
- 設定をオフにすると、それ以降は送りません。オフにする前に送ったものは、削除を依頼しない限り残ります。

## 8. 不正な送信への対応

虚偽の報告や大量の送信があった場合、その端末やIPアドレスからの受け付けを止め、送られたデータを削除することがあります。そのため、IPアドレスは変換した値(ハッシュ)としてだけ保存します。

## 9. 更新の確認と更新

- 起動時に、GitHub に最新のリリース情報を1回問い合わせます。GitHub には、通常のWebアクセスと同じ情報(IPアドレスなど)が届きます。GitHub での扱いは GitHub のプライバシーポリシーに従います。
- 「更新する」を押したときだけ、GitHub からインストーラーと確認用のファイル(SHA256SUMS.txt と署名)を取得します。作者に送るものはありません。
- 更新の確認は、設定の「CrashHunter について」→「起動時に更新を確認する」でオフにできます。

## 10. 変更

このページの内容を変えることがあります。変えた内容は、GitHub に載せた時点から適用します。送る情報を増やすなど大きな変更のときは、本ソフトの起動時にお知らせします。
